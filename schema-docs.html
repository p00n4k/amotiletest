Product Catalog — Schema & Data Dictionary

One catalog for tiles and furniture, with multi-image products, users & roles, and a full audit trail — who added, edited, discontinued, or repriced anything, and when. Every column is marked Manual (a user types it) or Auto (the system fills it).

Engine: SQLite Tables: 12 Units: CM · THB Source: schema.sql

Who provides what admin input vs system-generated

MANUAL Admin / user provides

The real catalog content. Someone types or chooses these when adding or editing a record.

  • ›Brand, category, collection names — the lookups
  • ›SKU and product type (tile / furniture)
  • ›Long description for the product detail page
  • ›Dimensions (width × length × height, in CM)
  • ›Images — main product photos and per-option photos (shown together), which is primary, order
  • ›Tile spec: price unit, price, sqm/box, pieces/box, kg/box, surface…
  • ›Furniture options: each configuration's price + its parts (Top / Base + material)
  • ›Users & roles — username, display name, role
  • ›Optional note / reason on an audit action

AUTO System creates by itself

Generated automatically the moment the admin saves — never typed by hand.

  • ›id — every primary key (autoincrement)
  • ›created_at / updated_at / deleted_at — all timestamps
  • ›created_by / updated_by / deleted_by — the logged-in user's id
  • ›status = 'active' — default on new brand / product
  • ›discontinued_at / by — stamped when "ไม่ขายแล้ว" is clicked
  • ›A price_history row — written on every price change
  • ›An audit_log row — written on every add / edit / delete / discontinue

What happens after the admin saves

  1. Admin logs in — the app now knows who they are (their users.id).
  2. Admin types the manual fields (SKU, name, price…) and clicks Save.
  3. System assigns the id, sets created_at = now and created_by = that user, and defaults status = active. → AUTO
  4. System writes one audit_log row: create · products · #id · by user. → AUTO
  5. Later, on any edit it stamps updated_at / by; on a price change it also inserts a price_history row. → AUTO

A product is exactly one type: tiles get one tile_specs row; furniture gets many product_options, and each option is made of several option_parts (Top, Base…). Both types can have many product_images.
Every table also carries created_by / updated_by / deleted_by / discontinued_by → users.id. Those arrows are omitted above to keep the diagram readable — the audit_log ties them all together.
